ทำไมต้องย้ายตอนนี้

คนร้ายกำลังเก็บทราฟฟิก IoT ของคุณวันนี้ เพื่อถอดรหัสในวันพรุ่งนี้

กลยุทธ์ "เก็บวันนี้ ถอดรหัสวันหลัง" (harvest-now, decrypt-later) ทำให้ RSA-2048 และ ECDSA ที่ใช้อยู่ทุกวันนี้จะกลายเป็นช่องโหว่ในอนาคต พอคอมพิวเตอร์ควอนตัมที่มีพลัง破解ทางคริปโตฯ มาถึง มันจะถอดรหัสได้ในไม่กี่ชั่วโมง ส่วนข้อมูลมิเตอร์ไฟฟ้า, GPS tracker และ telematics ของคุณยังคงอยู่บนสาย

  • อายุฮาร์ดแวร์ 10–20 ปี. มิเตอร์ที่ส่งออกปี 2024 จะอยู่จนถึงยุคที่ CRQC มาถึง
  • NIST ประกาศ ML-KEM และ ML-DSA ปี 2024. การย้ายแบบ hybrid เป็นมาตรฐานแล้ว ไม่ใช่การทดลอง
  • เขียน bootloader, driver และ OTA ใหม่แพงมาก. PULSE ส่งมอบแค่ชั้น crypto — firmware เดิมไม่เปลี่ยน

สิ่งที่คุณจะได้

ชั้น crypto แบบเสียบทันที ออกแบบมาเพื่อข้อจำกัดของอุปกรณ์ embedded

หก primitives ใน SDK เดียว ออกแบบมาเพื่ออุปกรณ์ที่ต้องอยู่ไปอีกสิบปี ไม่ใช่คลาวด์ที่จะเปลี่ยนใหม่อีกไตรมาส

FIPS 203 · ML-KEM (Key Encapsulation)

Kyber-768 + Kyber-1024 build/encapsulate/decapsulate · shared secret 32 ไบต์ ในเวลาคงที่

FIPS 204 · ML-DSA (Digital Signature)

Dilithium-3 + Dilithium-5 sign/verify · signature 2.4 KB ผ่านการตรวจสอบ side-channel

โหมด Hybrid (PQC + classical)

รัน ML-KEM คู่กับ X25519 พร้อมกัน ตัด classical ทิ้งหลัง OTA เสร็จ

KDF + RNG สำหรับ IoT

HKDF-SHA3 แบบเวลาคงที่ และ entropy mixer ที่ทน clock drift ของ MCU

OTA-safe key rotation

ตรวจสอบว่า firmware ใหม่เซ็นโดย trust anchor PQC ก่อน rebind key

Audit log ที่ตรวจสอบได้

ทุก key op ถูกเซ็นและส่งไป SIEM — ผ่าน SOC 2 CC6.1 และ IEC 62443-3-3

วิธีการทำงาน

สามคำสั่งเบื้องต้น ไม่ต้อง port firmware เดิม

สร้างคู่คีย์บนอุปกรณ์ → รับข้อความเข้ารหัสจากคลาวด์ → สร้าง session key ด้วย HKDF ทั้งหมดที่ต้องทำเพื่อย้ายระบบมีแค่นี้

  • เวลาคงที่ (Constant-time). ไม่มี data-dependent branch ตาม public-key path ทุกตัว
  • พกพาข้ามฮาร์ดแวร์. source C99 ตัวเดียวใช้ได้กับ Cortex-M0+, M4, ESP32-S3, ESP32-C3
  • ผ่าน MISRA-C. มีรายงาน MISRA-C:2012 advisory แนบทุก release
  • ผ่าน NIST CAVP. test vectors ตรวจสอบย้อนกลับได้กับ NIST CAVP ทุก primitive
